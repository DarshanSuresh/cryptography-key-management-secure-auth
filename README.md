# Cryptography, Key Management & Secure Authentication

Educational implementation of common secure cryptographic primitives in Python:

- AES-256-GCM authenticated encryption with random nonces
- RSA-2048 key-pair generation
- RSA-PSS digital signatures and verification
- Password hashing with bcrypt
- Secure key/secret storage and rotation guidance

> **Educational use:** These examples demonstrate correct primitives and secure handling patterns. For production systems, prefer well-maintained libraries and established key-management services rather than designing a custom cryptographic protocol.

## Security Notes

### AES-256-GCM
- Uses a fresh random 96-bit nonce for each encryption.
- Uses authenticated encryption, providing confidentiality and integrity.
- The nonce does not need to be secret, but **must never be reused with the same AES-GCM key**.
- Authentication tags are verified before plaintext is accepted.

### RSA
- Uses RSA-2048 for the requested demonstration.
- Uses RSA-PSS with SHA-256 for signatures.
- Private keys must remain secret.
- Signature verification should fail closed on invalid signatures.

### Passwords
- Passwords are hashed using bcrypt rather than encrypted.
- A unique salt is generated by bcrypt.
- The work factor should be chosen using current application performance/security requirements and reviewed periodically.
- Never store plaintext passwords.

### Secrets & Key Rotation
- Keep production secrets outside source control.
- Use a dedicated secrets manager/KMS where available.
- Restrict access using least privilege.
- Rotate keys according to risk and organizational policy.
- Maintain version/key identifiers so old ciphertext can be migrated safely.
- Revoke compromised credentials immediately.
